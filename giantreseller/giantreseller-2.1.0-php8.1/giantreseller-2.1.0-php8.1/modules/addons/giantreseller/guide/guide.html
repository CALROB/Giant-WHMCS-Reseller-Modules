1. What the module does

One provisioning module covers every Giant wholesale category. On each WHMCS product, you choose whether it is VoIP, Broadband, Mobile or UnifiedRPS, and which Giant product it orders.

  • When WHMCS creates the service, the module places the order with Giant and stores the Giant order and service ids against it.
  • Suspend, unsuspend, terminate and upgrade/downgrade in WHMCS are passed on to Giant.
  • Your customers see their service in your client area, in your wording. Giant's name, ids, carriers and suppliers are never shown to them.
  • Giant bills you at wholesale. You set your own sell prices in WHMCS.

It comes as two folders:

FolderWhat it is
modules/servers/giantresellerThe provisioning module. Products and servers use it.
modules/addons/giantresellerIts admin page: dashboard, reports, billing, Import products, Import services, Audit trail, Sync from Giant, Migrate from V1 and this guide.

2. Before you start

You needNotes
WHMCS 8.xPHP 7.4 or later, with the cURL extension.
Outbound HTTPSYour WHMCS server must be able to reach https://portal.giant.net.uk on port 443.
A Giant API keyIn the Giant portal: Partner area → API access. A live key is 34 digits and capital letters, e.g. 48203917562841K7QZ…, and places real orders. A sandbox key is the same with test_ in front, and runs everything in the sandbox (see section 12).
WHMCS cronMust be running. The module checks pending services once a day.

Setting up the key

  • Permissions: give the key the Full reseller preset. The module uses the catalogue, ordering, service lifecycle, VoIP, broadband, mobile, UnifiedRPS and invoice endpoints. A key without one of them gets a 403 forbidden answer for that part.
  • Allowed IPs: leave empty, or include your WHMCS server's public IP address. Calls from any other address get a 403 answer.
  • Sandbox keys read your real data but never change anything.
Example: check the key before you touch WHMCS From any computer with curl (the same works in Postman: import https://portal.giant.net.uk/partner/api/v1/openapi.json and set bearerToken): 
curl -H "Authorization: Bearer YOUR_API_KEY" https://portal.giant.net.uk/partner/api/v1/balance
A working key answers: 
{"data":{"credit":"125.40"}}
A wrong or inactive key answers 401 with {"error":{"code":"unauthorized", …}}. In that case, fix the key in the Giant portal first.
TipStart with a test_ key. Once a test order has gone end to end, swap it for your live key. Nothing else needs to change.

3. Install the files

  1. Copy both folders into your WHMCS installation so that you have: 
    <whmcs>/modules/servers/giantreseller/giantreseller.php
<whmcs>/modules/addons/giantreseller/giantreseller.php
  2. In WHMCS go to System Settings → Addon Modules, find Giant Reseller and click Activate. This creates the module's tables.
  3. Click Configure on the addon, tick the admin role groups that may use it (normally Full Administrator) and save.
  4. The page is now under Addons → Giant Reseller.

4. Add your Giant server

Go to System Settings → Servers → Add New Server and fill in:

FieldEnterWhy

Hostnameportal.giant.net.ukLeave blank to use this default.
ModuleGiant Reseller

Username, Access Hash, IPleave emptyNot used. A V1 server's username (a 32-character code) can be cleared.

Click Test Connection. When it succeeds, WHMCS writes a line to System Logs → Activity Log showing the mode and your credit.

Example: activity log after Test Connection 
Giant Reseller: Connected as sandbox, credit 125.40 via https://portal.giant.net.uk/partner/api/v1
With a live key it reads Connected (live).

Save the server. Then create a server group (Create New Group) and add the server to it. Your products will use this group.

The Billing tab of Addons → Giant Reseller now lists the server with its mode, credit, outstanding and overdue balance.

Dashboard and reports

Addons → Giant Reseller opens on the Dashboard:

  • Tiles: active services, what customers pay you per month, Giant's cost per month, your monthly margin, what you owe Giant and your Giant credit.
  • Charts: new services per month by category, what Giant invoiced you each month, and margin by category. Hover a bar for its figures, or use Show as table.
  • Needs attention: services not linked to Giant, services whose last Giant call failed, services Giant has ended, and orders Giant still hasn't built after two days.

The Reports tab has Margin by product, All services (filter by category and status) and Needs attention. Margin by product and All services also download as CSV.

Figures are refreshed every five minutes; Refresh fetches them now. Giant cost is Giant's price for each product and its configurable options (those synced from Giant) on the cycle Giant bills you. Usage, such as call charges, and one-off charges aren't in it; the Giant invoices chart is the real spend. Money is shown in your WHMCS default currency.

Paying Giant invoices

When you owe Giant anything, the Billing tab lists the unpaid invoices that make up Outstanding, with overdue ones in red. You can pay:

  • One invoice: Card / DD charges the card or Direct Debit on your Giant account. Credit uses your Giant account credit, and only appears when you have some.
  • Everything: Pay all … from card / Direct Debit on file, or Pay all from credit. Invoices are paid oldest first, and with credit it stops when the credit runs out.

Each button asks you to confirm first. The result is shown straight away and recorded in the activity log.

Who can pay: by default only the Full Administrator role. To let other roles pay, enter their role ids, comma-separated, under System Settings → Addon Modules → Giant Reseller → Configure → Who can pay Giant invoices. The ids are listed under the box. Admins in other roles see the invoices but no Pay buttons, and a payment they post by hand is refused.

Example: Pay all, where one card payment is declined 
Some invoices were not paid. 114.80 paid in total.
  Invoice 30412: Paid, 114.80 taken
  Invoice 30655: Not paid, 848.15 still to pay. The payment was declined or could not be taken.
A decline takes nothing. Giant allows one attempt per invoice every 10 minutes (and one Pay all every 10 minutes), so try again later or pay that invoice from credit. With a sandbox key every check runs and nothing is taken.

  4. Choose the Billing cycle and Payment method, then save.
  5. Choose when WHMCS should create the service (e.g. when the first payment is received, or when you accept the order).

Import many products at once

Rather than set products up one by one, use Addons → Giant Reseller → Import products. It lists Giant's wholesale range, filtered by category if you like, with Giant's prices. It also shows what you have already imported.

  1. Tick the products you want. Change Your product name if you like: customers see this name.
  2. Choose the settings for the new products:
    SettingWhat it does
    Product groupOne group per category (VoIP, Broadband, Mobile, UnifiedRPS), created if missing, or one of your existing groups.
    Server groupThe group holding your Giant server.
    Pay Giant byThe payment method set on every new product.
    Giant bills youThe preferred cycle. A product that doesn't have it uses its first priced cycle.
    Your markupA percentage on Giant's price, applied to every cycle, setup fee and option choice. Prices are rounded up to .99, or kept to the penny. Other WHMCS currencies are converted at your exchange rates.
    Create the serviceWhen WHMCS should place the Giant order. When I accept the order is the default and the safest.
    AlsoCreate hidden (on by default). Sync from Giant (on by default). Copy Giant's description (off: it can name networks or suppliers). Import products again that were imported before.
  3. Click Preview. You see each product's sell prices and where it will go, and nothing is created yet.
  4. Click Import. Each product is created on this module, synced, and its new option choices are priced at the same markup.
  5. Check the products, then untick Hidden on each one when you're ready to sell it.

6. Sync from Giant

Many Giant products need information at order time, such as an installation address reference or a router choice. Sync from Giant copies those questions onto your product as WHMCS custom fields and configurable options.

  1. Save the product with its Giant product chosen.
  2. Click the Sync from Giant link under the Giant product setting. You can also click it on the addon's Products tab.
  3. Check the product and click Sync now.

The sync then:

  • creates or updates custom fields with Giant's plain names, descriptions, types, options and required flags;
  • creates or updates a configurable option group named after the Giant product and links it to your product;
  • never deletes anything. What Giant no longer has is listed as No longer on Giant for you to remove by hand;
  • never changes your prices. New options start at 0.00.
Example: first sync of "Business FTTP 500" 
Synced. fields 1 added; options 2 added.

Custom fields
  Added      Installation address UPRN

Configurable options
  Added      Router, Router › Managed router
Run it again and everything reads Unchanged. Run it after Giant changes the product to pick up the changes.

Sync only runs when you click it. If a product has never been synced, the module orders without custom fields. If Giant needs any, it refuses the order and the admin sees Giant's message.

VisibilityNew fields are created to show on the order form. You can untick that, or tick Admin only, on the field. Later syncs keep your choice.

7. Set your prices

Set your sell prices on the product's Pricing tab and on each configurable option, as for any WHMCS product. Giant invoices you at wholesale for what you order. The addon's Dashboard shows your margin per month, and its Billing tab shows your credit and what you owe.

ExampleGiant's wholesale price for Business FTTP 500 is £42.00 a month. You set £59.00 a month in WHMCS, and £5.00 a month on the Managed router option. Your customer pays you £64.00, and Giant bills you the wholesale amounts.

8. Orders and the admin service tab

When WHMCS creates the service (automatically, or with Module Commands → Create):

  1. The module sends the order to Giant with the product, cycle, payment method and the customer's answers to the synced fields and options.
  2. Giant returns an order id. The module saves it against the service straight away.
  3. The module reads the Giant service and copies the username, domain and dedicated IP onto the WHMCS service. Everything after that, VoIP included, is reached by the Giant service id alone.

If Giant hasn't built the service yet (common for broadband), the order still succeeds. The module checks again every hour, or click Refresh from Giant.

Example: the service's module tab after ordering
Giant order48213
Giant service id9877
Categorybroadband
Giant statusActive
Last synced2026-10-14 09:42:10
Last error—
Link to Giant order(empty box: see section 11)
A sandbox order shows the Sandbox order badge.

Refresh from Giant (a module button on the service) re-reads the service from Giant immediately.

Placing an order twice is blockedIf you press Create on a service that already has a Giant order, the module answers Already ordered as Giant order 48213. It does not place a second order.

9. Suspend, upgrade, terminate

In WHMCSWhat happens at Giant
SuspendThe Giant service is suspended. Your suspension reason is passed on.
UnsuspendThe Giant service is reactivated.
TerminateThe Giant service is terminated, and Giant status becomes Terminated. This cannot be undone.
Upgrade / DowngradeIf the new WHMCS product orders a different Giant product, the service moves to that product. If it's the same Giant product, the new configurable option values are sent instead.
RenewNothing. Giant bills you directly.

If Giant refuses, WHMCS shows Giant's reason. It's also saved as Last error on the service tab.

Example messages 
Giant API (403 not_available): Product 99 is not in your wholesale range.
Giant API (409 conflict): Cancel the router order first.
Not linked to a Giant order
Services ended at GiantIf the daily check finds a service that Giant reports Terminated or Cancelled while WHMCS still has it Active, the module raises an admin to-do item, Giant service ended: WHMCS service #1234, and records the reason on the service. It never changes WHMCS's status by itself.

Untick a box on the product's Module Settings tab to take that action away. Its button disappears from the client area, and the module refuses it even if someone posts it by hand. Products made by Import products or the V1 migration start with every box ticked.

Example: handsets customers can add but not remove UnifiedRPS: customer can add stays ticked; untick UnifiedRPS: customer can remove. The customer enters Yealink and 80:5E:C0:12:34:56. Your wording. Every customer-facing text is in modules/servers/giantreseller/lang/english.php. Edit it to match your brand. For other languages, copy it to <language>.php, e.g. french.php. Errors are shown to customers in general terms; the detail is in the module log for you.

Example: changing a message 
'setting_up' => 'Thanks for your order! Your Acme Broadband line is being set up.',

Pages are cached for 60 seconds per service, so a refresh doesn't hit the API every time.

11. Linking services you already have

For a service created outside the module, for example ordered in the Giant portal, you can link it to its Giant order:

  1. Open the service in WHMCS. Make sure its product uses the Giant Reseller module with the right category.
  2. Type the Giant order id into Link to Giant order on the module tab, e.g. 48213.
  3. Click Save Changes. The module checks the order is on your account before linking, then reads the service.

If the order isn't yours, the service tab and activity log show Giant has no order 48213 on this account.

Bringing many existing Giant services into WHMCS

If you have Giant services that WHMCS doesn't know about yet, for example ones ordered in the Giant portal, use Addons → Giant Reseller → Import services. It lists every Giant order on your account that no WHMCS service is linked to, with its product, domain, billing cycle and Giant status.

  1. Tick the orders you want to bill through WHMCS.
  2. For each one, choose the WHMCS product (✓ marks products that order the same Giant product) and find the client: type part of their name, company or email (or a client id) and pick them from the list. Clicking into an empty client box suggests clients like the name Giant has on the service, and picking one ticks the row.Optionally set the next due date; blank uses the day Giant next bills you.
  3. Choose how the customer pays (a WHMCS payment gateway), and whether the new services start Active.
  4. Preview checks every row: it finds the client and reads each service from Giant. Then Import.

Each import creates the WHMCS service with WHMCS's own order process, with no invoice and no emails. It then links the service to its Giant order and copies across the domain, username and any synced custom field values. No new Giant order is placed: even a product set to create the service as soon as it's ordered links to the existing Giant order instead.

Example
Giant orderGiant serviceWHMCS productClient

12. Testing with a sandbox key

A test_ key works against the same address as a live key. Every check runs, but writes are simulated: nothing is ordered, billed or provisioned.

  • Test Connection reports Connected as sandbox, and the addon's Billing tab shows Sandbox.
  • Sandbox order ids are above 900000000, e.g. 912345678, and the service tab shows the Sandbox order badge.
  • The daily check skips sandbox services. Sandbox services are never migrated.
Example test run
  1. Server with a test_ key → Test Connection → Connected as sandbox.
  2. Product "Test FTTP" → Sync from Giant → order it as a test client → accept.
  3. Service tab: Giant order 912345678 Sandbox order.
  4. Suspend, Unsuspend, Upgrade, Terminate: each returns success.
  5. Swap the server's password for your live key when you're happy.

13. Moving from the V1 modules

If you used the older GiantResellerApiProv or GiantResellerVoIPApi modules, open Addons → Giant Reseller → Migrate from V1. Run each step as a Dry run first: it shows what will change without changing anything. Every step is safe to run again.

StepWhat it does
1. ServersV1 servers held a password for the retired API. Paste a v1 API key for each. The key is checked with Giant first, then Check and switch moves the server to this module.
2. ProductsMigrate products switches each V1 product to this module, carrying over its Giant product, cycle and payment method. It renames old id|name fields and options to plain names (customer values are kept), then runs Sync from Giant.
3. Service linksImport links copies every V1 order link into this module. V1's tenant columns aren't needed: VoIP is reached by the Giant service id.
4. Old tablesOnce you're happy, Drop old tables removes the V1 link tables. This cannot be undone.
Example: dry run of step 2 
Business FTTP 500
Giant product 12 (Business FTTP 500), broadband, monthly, pays by banktransfer.
Would rename field "41|Installation address UPRN" to "Installation address UPRN".
Would rename option group "Business FTTP 500 (5|12)" to "Business FTTP 500".
Would rename option "7|Router" to "Router".
Would switch to giantreseller and sync from Giant.
Do step 1 firstProducts can only move once their server has a v1 key. Until then, step 2 reports Switch its server first.

Remove the old module folders (modules/servers/GiantResellerApiProv, modules/servers/GiantResellerVoIPApi) only after every product has moved.

14. Troubleshooting

Every call to Giant is written to System Logs → Module Log (turn it on first) as giantreseller, e.g. POST /orders, with your API key hidden. That's the place to look first.

You seeMeaningFix
Giant API (401 …): the API key was refused. Check the API key on the server. Key sent: 4820…XQ2M, 34 characters.Giant has no active key matching what was sent. Key sent shows the first and last four characters and the length.Compare it with the key in Partner area → API access, and try the key with curl (section 2). A live key is exactly 34 digits and capital letters (39 with test_). A different length usually means a pasted space or the old V1 password. If it matches, check the key is active and not revoked. Paste it again into the server's Password field and save.
Giant API (403 forbidden): This key may not call this endpoint (its permissions, its allowed IPs, or your account's API access).The key is valid but limited.In Partner area → API access, give the key the Full reseller preset. If it has allowed IPs, add your WHMCS server's public IP.
Giant API: could not connect (…)WHMCS can't reach Giant.Check outbound HTTPS to portal.giant.net.uk, DNS, and the PHP cURL extension.
Module settings incomplete: Giant product, Payment method.The product isn't fully set up.Finish the Module Settings tab (section 5).
Giant API (400 invalid): …Giant rejected a value, often a required field left empty.Sync the product (section 6) and make sure customers fill in required fields.
Giant API (403 not_available): …Product outside your wholesale range.Choose a product from the list. The range can change, so re-check the product's settings.
Giant API (409 not_ready): …Giant is still building the service.Nothing. Try again later, or wait for the daily check.
Giant API (422 refused): …Giant can't do this, for the reason given.Act on the message. It's written for people.
Giant API (500): Giant could not complete this just now.A temporary problem at Giant.Try again shortly. The module never retries orders by itself.
Unlinked: Giant API (404 not_found): …Giant has no service for that order any more.Check the order in the Giant portal. Re-link the service (section 11) or close it in WHMCS.
Not linked to a Giant orderThe service has no Giant order.Create it, or link it (section 11).
